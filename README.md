# WMS — warehouse management demo

A small warehouse management system for two buildings:

- **PJ01**: clinical and laboratory shipments (bottles, dry-ice preparation, temperature groups)
- **FG01**: commercial finished goods (pallet shipments, truck loading)

Every unit of work (an ERP shipment, a dry-ice prep, a truck loading, a re-supply…) is a task with a status, a priority and a due date. Each task is converted into **work units (WU)** through a configurable matrix, and the WU are compared with daily staff capacity.

> All data in this demo is fictional: the companies, carriers (apart from DHL, FedEx and UPS), people and volumes are generated by `scripts/seed.ts`.

## Features

- **Live dashboards** per building, for wall screens: tasks grouped by date and recipient, dry-ice preps linked to their shipment, groupage of shipments that leave together, and today's and tomorrow's utilisation.
- **Backoffice**: search, filters, bulk status and CMR updates for groupages, RDR26 closing and PGI tracking, and CSV export.
- **Capacity planning**: per-collaborator presence, 10 working-day capacity vs workload.
- **Work unit matrix** (admin): coefficients per task type, carrier, temperature group and category.
- **Analytics**: status and type distribution, workload trend.
- Realtime updates through Supabase, installable as a PWA.

## Stack

React 19, TypeScript, Vite, Tailwind CSS, TanStack Query, Recharts, Supabase (Postgres, Auth, Realtime, row-level security).

## Getting started

```bash
npm install
cp .env.example .env      # Supabase URL + publishable key
npm run dev
```

### Database

`supabase/schema.sql` creates the whole schema. `scripts/seed.ts` fills it with a reproducible demo dataset (fixed random seed): 12 months of history plus the next two weeks.

```bash
# Rebuild the schema and load the demo data (DESTRUCTIVE)
DATABASE_URL="postgresql://…" npm run db:reset

# Reload the demo data only
DATABASE_URL="postgresql://…" npm run db:seed

# Preview the generated volumes without touching the database
node scripts/seed.ts --dry-run
```

Optional variables:
- `SEED_ANCHOR=YYYY-MM-DD` pins "today". It defaults to the current date.
- `ADMIN_EMAIL` grants the admin role to an existing account.

New sign-ups get the `operator` role. The demo account is `demo@example.com`.
